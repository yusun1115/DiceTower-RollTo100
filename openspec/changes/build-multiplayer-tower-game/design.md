# Design

## Context

이 프로젝트는 OpenSpec만 초기화된 그린필드 프로젝트이며 기존 코드, 서버, 데이터 모델, 테스트가 없다. 자세한 사용자 가치와 기능 범위는 `proposal.md`를 참조한다. 핵심 제약은 PC 브라우저의 2D 탑다운 실시간 전투, 순차 턴, 공통 던전 구성, 플레이어별 독립 전투 상태, 그리고 온라인·CPU 모드의 규칙 일치다.

## Goals / Non-Goals

**Goals:**

- 동일한 경기 규칙을 온라인 1대1과 CPU 대전에 적용한다.
- 네트워크 지연이나 클라이언트 조작으로 주사위, 피해, 상점 재고, 승패가 달라지지 않도록 한다.
- 공통 시드로 같은 장소를 탐험하는 느낌을 주면서 각 플레이어의 전투 결과와 보상은 독립적으로 유지한다.
- 아이템을 데이터 중심의 효과 조합으로 정의해 새로운 무기·버프·시너지를 추가할 때 핵심 전투 코드를 반복 수정하지 않도록 한다.
- 짧은 일반층과 긴 보스층의 시간을 제한하고, 무적 유령으로 비활성·지연 플레이를 종료시킨다.

**Non-Goals:**

- 첫 버전에서 모바일 터치 조작을 지원하지 않는다.
- 첫 버전에서 공개 랜덤 매칭, 친구 목록, 랭킹, 계정 영속화는 포함하지 않는다.
- 100개 층을 각각 완전히 수작업으로 만드는 대신 재사용 가능한 방·적·장애물·보상 데이터로 층을 구성한다.
- 플레이어 간 동시 실시간 전투는 지원하지 않는다. 한 번에 한 플레이어만 던전 행동을 수행한다.

## Decisions

### 1. 서버 권위형 세션 상태

세션 권위자는 턴 소유권, 주사위, 층 전환, 타이머, 피해, 아이템 구매, 유령 접촉, 최종 승리를 검증하고 결과를 두 클라이언트에 전달한다. 브라우저는 입력과 렌더링을 담당하지만 최종 상태를 결정하지 않는다.

대안으로 피어 투 피어 판정을 고려할 수 있지만, 한 플레이어가 주사위·피해·상점 재고를 조작할 수 있고 지연 시 상태가 갈라질 위험이 커서 선택하지 않는다. 양방향 실시간 전송 채널은 필요하지만 구체적인 웹 프레임워크는 구현 단계에서 확정한다.

### 2. 명시적인 세션 상태 머신

세션은 다음 상태와 전이를 중심으로 구현한다.

```text
[Lobby]
   |
   v
[Roll] --> [Floor Setup] --> [Combat or Shop]
   ^                              |
   |                              v
   +------ [Death] <-------- [Resolved]
                                  |
                                  v
                           [Next Player Turn]
                                  |
                                  v
                              [Victory]
```

각 전이는 권위자만 수행한다. 일반·보스 전투는 모든 필수 몬스터 처치 또는 사망으로, 상점은 쇼핑 종료로 해결된다. 최종보스 처치는 일반적인 다음 턴 전환보다 우선해 세션을 종료한다.

### 3. 공통 시드와 개인 전투 인스턴스

경기 시작 시 하나의 시드에서 층별 블루프린트를 파생한다. 블루프린트에는 방 구조, 장애물, 적 종류·수량, 상자 위치와 보상 후보, 초기 상점 상품을 포함한다. 플레이어가 실제로 몬스터를 처치하고 피해를 입고 상자를 여는 상태는 개인 인스턴스에 저장한다.

이렇게 하면 두 플레이어가 같은 3층의 고블린 3마리를 경험하면서도 1P의 처치가 2P의 전투를 건너뛰게 만들지 않는다. 테스트는 경기 시드와 층 번호를 입력으로 받아 같은 블루프린트를 재현할 수 있어야 한다.

### 4. 상점은 세션 수준의 공유 자원

상점 재고와 재생성 타이머는 개인 플레이어 상태가 아니라 세션에 속한다. 구매는 코인 차감과 재고 삭제를 한 번의 원자적 상태 전환으로 처리한다. 구매 후 세 번의 플레이어 턴이 지나면 전체 재고를 같은 규칙으로 다시 생성한다. 한 번 방문에서 여러 구매를 허용하되, 각 구매는 최신 재고와 잔액을 다시 검증한다.

던전 상자는 블루프린트상 같은 후보와 보상량을 사용하지만 개인 인스턴스에서 각각 열 수 있게 한다. 이로써 상점에는 경쟁을, 던전 탐험에는 대칭적인 기회를 준다.

### 5. 데이터 중심 아이템 효과

아이템은 최소한 `trigger`, `target`, `effect`, `duration`, `tags`, `risk` 속성으로 표현할 수 있는 콘텐츠 데이터로 설계한다. 예를 들어 검은 공격 효과를, 원거리 태그는 투사체 효과를, 이동 트리거와 가시 효과는 이동 경로 위험물을 만든다. 효과 처리기는 보유 아이템 목록을 평가해 호환되는 효과를 순서대로 적용한다.

강력한 무기는 구성 데이터로 1개 전투층, 일반 무기는 최대 5개 전투층처럼 지속시간을 가진다. 패시브 버프는 경기 동안 유지하며, 상점층은 무기 지속시간을 차감하지 않는다. 소유자에게도 피해를 줄 수 있는 위험 효과는 몬스터에게 적용하는 동일한 피해·충돌 규칙을 재사용한다.

### 6. CPU는 동일한 행동 경로를 사용

CPU는 서버 또는 권위 있는 세션 런타임에서 같은 합법 행동 명령을 생성하고, 일반 참여자와 동일한 검증기를 통과시킨다. 난이도는 숨겨진 보너스가 아니라 의사결정 주기, 목표 선택, 회피, 구매 우선순위, 아이템 시너지 활용으로 차이를 만든다. 초기 구현은 보통 난이도의 기본 행동을 완성하고 쉬움·어려움은 동일한 행동 인터페이스의 정책 차이로 추가한다.

### 7. 시간 초과와 유령

층 타이머는 권위자 시계로 판정한다. 일반층은 90초, 미니보스층은 180초, 최종보스층은 300초다. 시간 초과 시 유령 상태를 전투 인스턴스에 추가하고, 유령은 충돌 판정 시 지형 차단을 무시한다. 접촉 이벤트는 하트 감소가 아니라 즉시 사망 이벤트를 발생시키며, 층 하락·아이템 유지 등 일반 사망 해결을 재사용한다.

## Risks / Trade-offs

- [네트워크 지연] → 입력과 렌더링은 반응적으로 처리하되, 주사위·피해·구매·전환은 권위자의 순서 번호가 있는 이벤트로 확정한다.
- [아이템 조합 폭발] → 태그·트리거·효과의 조합 수를 데이터 검증으로 제한하고, 조합별 테스트 픽스처를 둔다.
- [100층 콘텐츠 제작량] → 층 번호를 고정된 수작업 맵이 아니라 검증된 방 템플릿과 난이도 곡선으로 생성한다.
- [CPU가 너무 쉽게 예측됨] → 정상 규칙을 유지한 채 타깃 선택과 구매 정책을 단계별로 개선하고, 어려움 난이도에는 반응 지연과 실수 확률을 별도로 조정한다.
- [공유 상점의 동시 구매 경쟁] → 모든 구매를 순차적인 세션 이벤트로 처리하고, 두 요청이 같은 재고를 가리키면 먼저 확정된 요청만 성공시킨다.
- [유령의 즉사 체감] → 유령 등장 시 명확한 시각·음향 경고와 충분히 느린 초기 속도를 제공해 시간 초과와 접촉 사이에 회피 기회를 남긴다.

## Migration Plan

기존 구현이 없는 그린필드 변경이므로 데이터 마이그레이션은 없다. 먼저 세션 상태와 결정적 시드를 포함한 단일 플레이어 수직 슬라이스를 만들고, 같은 검증 경로에 CPU를 연결한 뒤 방 코드 기반 온라인 세션을 추가한다. 부분 구현을 배포할 때는 온라인 매치를 노출하기 전에 로컬·CPU 검증을 통과했는지 확인한다.

롤백은 신규 게임 진입 경로와 세션 서비스를 비활성화하는 방식으로 수행하며, 기존 사용자 데이터 복구는 필요하지 않다.

## Open Questions

- 구체적인 아트 스타일, 방 크기, 몬스터 수, 아이템 가격과 수치는 콘텐츠 데이터 조정으로 처리하며 핵심 계약을 바꾸지 않는다.
- 공개 매칭, 계정 저장, 모바일 입력은 후속 변경에서 별도 범위로 결정한다.
